# 염주 온라인

**천천히 걷고, 함께 절하고, 나만의 염주를 잇는 온라인 사찰 힐링 게임.**

실제 게임 촬영: [전체 플레이 화면](docs/screenshots/gameplay.png) · [법당 안 화면](docs/screenshots/temple.png) · [남녀 스님 모델](docs/screenshots/monks.png)

브라우저에서 플레이하는 첫 번째 버전입니다. React·Three.js 클라이언트와 서버 권한 방식의 WebSocket 게임 서버로 구성했습니다. 화면 속 다른 순례자는 실제 같은 채널에 접속한 사용자이며, 접속 인원이나 채팅을 가짜 데이터로 채우지 않습니다.

## 시작하기

Node.js **24 이상**이 필요합니다. 이 클라우드 환경에는 Node 24와 Chromium이 준비되어 있습니다.

```bash
cd /workspace/yumjuuu
npm ci
npm run dev
```

개발 클라이언트는 5173번, 게임 서버는 3001번 포트에서 실행됩니다. Vite가 `/api`와 `/ws`를 서버로 전달합니다. 터미널에서 Ctrl+C를 누르면 두 프로세스를 종료합니다. API 준비 상태는 `GET /api/health`로 확인할 수 있습니다.

배포용 클라이언트를 만들고 같은 출처에서 제공하려면:

```bash
npm run build
npm start
```

`npm start`는 3001번 포트에서 정적 클라이언트와 API, WebSocket을 함께 제공합니다. 외부 서비스나 API 키는 필요하지 않습니다. 서체와 3D 모델은 로컬에서 제공하며, 배경음도 사용자 선택 후 브라우저에서 생성합니다.

## 지금 할 수 있는 것

- **10개 테마 채널:** 청죽의 뜰, 연화의 못, 솔바람 산사, 월하의 정원, 새벽 종소리, 설송의 암자, 단풍의 길, 운무의 숲, 금강의 능선, 천년 향림. 각 채널은 최대 **108명**이며 색감과 드롭 목록이 다릅니다.
- **넓은 사찰 탐험:** 대웅전·관음전·약사전·명상전과 12개 채집 지점. 일주문, 대숲, 꽃나무, 연못과 돌탑이 있는 입체 공간입니다.
- **큰 법당과 108개 수행 자리:** 대웅전은 폭 35·깊이 23, 세 부속 법당은 폭 25·깊이 17 월드 단위입니다. 높은 단청 천장과 금빛 불단 앞에 대웅전 48개, 나머지 법당 각각 20개의 방석과 목탁을 배치했습니다.
- **삭발한 귀여운 스님 캐릭터:** 회색 승복과 왼쪽 어깨를 덮는 가사를 입습니다. 프로필에서 남성·여성을 선택할 수 있으며 재접속해도 선택을 유지합니다.
- **착석과 개인 목탁:** 비어 있는 방석에 앉아 절하거나 목탁을 두드릴 수 있습니다. 목탁 소리는 해당 브라우저에서만 합성하며 다른 접속자에게 전송하지 않습니다. 배경음과 별도로 목탁 소리를 끌 수 있습니다.
- **채집과 절:** 채집은 재료 1개를 보장하며 장소마다 8초 후 재생성됩니다. 절은 기본 3초이며 완료할 때 개인 드롭을 추첨합니다. 이동하면 절이 취소됩니다.
- **공동 108배:** 채널과 법당별로 절 횟수를 합산합니다. 108회를 채우면 최근 10분 안에 그 법당에서 기여하고, 보상 시점에도 법당 주변에 있는 접속자에게 추가 재료를 지급합니다.
- **염주 조합:** 염주알 10종과 염주띠 6종, 일반·고급·희귀·영웅·전설 등급. 띠에는 8~108개의 알을 끼울 수 있습니다. 이동 속도·절 속도·발견 확률을 조합하고 다른 플레이어의 캐릭터를 눌러 염주를 구경할 수 있습니다.
- **실시간 도반과 대화:** 같은 채널의 캐릭터와 채팅을 동기화합니다. 이름을 바꾸고 채널을 옮겨도 소지품과 개인 수행 기록을 유지합니다.
- **개인 기록 보관:** HttpOnly 쿠키와 SQLite로 이름·성별·인벤토리·장착·누적 절 횟수를 보관합니다. 재접속·서버 재시작 후에도 복구합니다. 계정 가입·다른 기기로 이전·아이템 거래는 아직 없습니다.

### 플레이 화면

접속하면 산사를 직접 걷는 3인칭 플레이 화면으로 시작합니다. 화면 가장자리의 간결한 HUD에서 현재 채널·실제 접속 인원·자신의 능력치와 기록을 확인할 수 있습니다. 오른쪽 아래 안내도는 현재 위치와 법당·채집 장소를 표시합니다. 안내도를 누르거나 M을 눌러 큰 지도를 열 수 있습니다.

‘마우스로 둘러보기’를 누르면 브라우저의 커서 잠금을 시작합니다. 이 기능은 사용자 선택 후에만 켜지며, 잠금이 제한된 환경에서도 우클릭 드래그로 시점을 돌릴 수 있습니다. 우측 위 축소 아이콘을 누르면 염주함과 수행 기록을 살펴보는 기본 화면으로 전환됩니다.

우측 위 **화질**에서 자동·높음·보통·낮음을 선택할 수 있으며 선택은 이 브라우저에 저장됩니다. 자동은 기기의 화면 부하에 맞춰 해상도와 그림자를 조절합니다. 원활한 조작이 우선이면 자동 또는 낮음을, 충분한 그래픽 성능이 있으면 높음을 선택하세요. 화질을 바꿔도 산사 접속과 개인 기록은 유지됩니다.

| E                                  | 가까운 방석에 앉기 / 절 / 선물 줍기  |
| F / 목탁 두드리기                  | 착석한 자리의 목탁 두드리기          |
| 일어나기 / 이동                    | 방석에서 일어나 자리 비우기          |
| I / 염주함                         | 구슬·띠 장착과 해제                  |

| 마우스 오른쪽 버튼 + 드래그        | 캐릭터 주위로 시점 회전              |
| 모바일 화면 드래그 / 가볍게 누르기 | 둘러보기 / 해당 위치까지 걷기        |
| 마우스 시점 버튼 / Esc             | 커서를 잡고 둘러보기 / 커서 해제     |
| 화면 전환 / Esc                    | 3인칭 플레이 화면과 기록 화면 전환   |
| M / 오른쪽 아래 안내도             | 산사 전체 지도 열기                  |
| Enter / 마당 이야기                | 같은 채널의 도반과 채팅              |
| 모바일 방향 조작판                 | 누르는 동안 바라보는 방향으로 걷기   |
| 스피커 버튼                        | 잔잔한 배경음 켜기·끄기              |
| 목탁 소리 버튼                     | 본인의 목탁 소리 켜기·끄기           |

카메라는 캐릭터 뒤에서 앞을 바라보는 3인칭 원근 시점입니다. 마우스 오른쪽 버튼을 누르고 움직여 주변을 둘러보세요. 마우스 시점 기능은 브라우저가 커서 잠금을 허용할 때 사용하며, 잠금이 제한된 환경에서는 오른쪽 드래그를 사용하면 됩니다. 플레이 화면에서도 염주함·지도·도움말과 채팅을 열 수 있습니다. 모바일에서는 화면 드래그로 둘러보고, 왼쪽 아래 방향 조작판을 누르는 동안 걸을 수 있습니다. 커서가 잠긴 상태에서 Esc를 누르면 먼저 커서가 풀리고, 다시 Esc를 누르면 집중 화면을 닫습니다.

기본 걷기는 초당 2.8, Shift를 누른 빠른 걸음과 자동 이동은 초당 4.2 월드 단위입니다. 이동 속도 장비 효과는 여기에 곱해지며, 서버도 같은 최대 속도로 검증합니다.

법당으로 이동한 뒤 **방석 찾아가기**를 누르거나 방석·목탁을 직접 누르면 빈자리로 걸어가 앉습니다. 앉아서 절을 마친 뒤 F 또는 **목탁 두드리기**를 누르면 자신의 목탁 소리만 들립니다. 같은 채널에서 한 자리를 동시에 차지할 수 없으며 이동·접속 종료·채널 이동 시 자리를 비웁니다. 다른 도반에게는 앉은 자세가 보입니다.

한 브라우저에서 여러 창을 열면 동일한 순례자로 취급하고 마지막으로 입장한 창에 접속을 넘깁니다. 두 명을 시험하려면 서로 다른 브라우저 프로필 또는 시크릿 창을 이용하세요. 쿠키를 삭제하면 이전 기록을 찾을 수 없으므로 주의하세요.

### 재료와 능력치

소나무·대나무·단풍나무 → 향나무·대추나무 → 회양목·백단 → 자단 → 흑단·침향 순으로 게임 내 희귀도를 정했습니다. 소재의 밀도·내구성·희소성과 게임 균형을 함께 반영한 설정이며, 실제 목재의 강도 순위를 엄밀하게 나타내지는 않습니다.

띠는 삼베·무명·아마·명주·오색 금강매듭·백팔 금강염주띠로 이어집니다. 능력치는 합산하되 이동 속도 +75%, 절 속도 +200%, 발견 확률 +100%를 상한으로 적용합니다. 절 소요 시간은 `3초 ÷ (1 + 절 속도 / 100)`입니다.

절의 개인 드롭 확률은 `min(95%, 65% + 발견 확률 / 250)`이며, 발견 확률 능력치는 희귀 이상 재료의 상대 가중치도 높입니다. 예를 들어 발견 확률 +25% 장비를 착용하면 절 드롭 확률은 75%입니다. 테마 내 아이템별 확률은 등급 가중치를 정규화한 값으로, 테마마다 후보가 달라 동일 등급의 최종 확률도 다릅니다.

## 검증

```bash
npm test
npm run build
npm run test:e2e
```

서버 통합 테스트는 실제 HTTP·WebSocket 연결을 사용합니다. 이동 검증, 채집 거리·재생성, 장착, 절 취소·완료, 공동 보상, 채널 격리, 정원 초과, 출처 검증, SQLite 복구, 자리 점유·해제와 성별 저장을 확인합니다. 실제 연결 108개 입장과 109번째 거절도 별도로 확인합니다.

브라우저 테스트는 실제 3D 화면, 키보드 이동, 채집→장착→재접속, 절과 공동 진행률, 두 브라우저의 채팅·채널 분리, 모바일 레이아웃을 확인합니다. 시스템 Chromium이 없으면 `npx playwright install chromium`을 실행하세요. 별도 Chromium 경로는 `PLAYWRIGHT_CHROMIUM_PATH`로 지정할 수 있습니다. 테스트가 필요한 개발 서버를 자동으로 실행합니다.

## 구조와 다음 단계

그래픽은 둥근 얼굴과 삭발 머리의 귀여운 남녀 스님, 승복·가사와 걷기·절·착석 애니메이션, 입체 기와·공포·창살·현판과 금빛 불단을 가진 법당, 솔잎과 가지를 표현한 소나무, 여러 겹의 산 능선으로 구성했습니다. 목재·석재·기와·흙·천의 색상·요철 텍스처는 로컬에서 생성하고, 원근 카메라·대기 산란 하늘·방향광 그림자·접지 그림자를 사용합니다.

정적 월드는 재질과 공간 구역별로 병합해 UV와 시야 밖 객체 제거를 유지합니다. 카메라 충돌은 세밀한 기와 전체 대신 단순한 건물 충돌체로 계산합니다. 멀리 있거나 혼잡한 원격 캐릭터는 병합 모델로 전환하고, 가까운 도반 최대 8명과 본인에게 관절 애니메이션을 적용합니다. 픽셀 밀도는 1.5배로 제한하고 그림자는 초당 최대 20회 갱신합니다. 이 선택들은 비용을 줄이기 위한 구현이며, 1,080명 동시 플레이의 프레임 성능을 입증하는 부하 시험은 아닙니다.

```text
src/                 React 화면, Three.js 월드, 연결·배경음
src/world/           캐릭터·법당·자연환경·표면 재질
src/moktakAudio.js   해당 브라우저에서만 합성하는 목탁 소리
shared/game.js       테마·법당·채집 지점·아이템·장비 능력치
shared/templeLayout.js 법당 치수와 108개 방석·목탁 좌표
server/index.js      HTTP·WebSocket, 게임 규칙, SQLite
tests/              서버 통합 및 실제 브라우저 테스트
```

현재 **서버 한 프로세스 안의 논리 채널 10개**입니다. 서버 10대를 배포한 구성은 아닙니다. 1,080명의 지속적인 동시 플레이 성능은 아직 검증하지 않았습니다. 서버가 보상·속도·거리·정원을 검증하고, 10Hz 동기화·입력 제한·느린 연결 차단을 적용했습니다. 클라이언트는 정적 사찰 모델을 재질별로 병합하고 캐릭터 모델을 재사용하며 픽셀 밀도를 제한합니다.

공개 운영 전에는 채널별 룸 서버 분리, 관심 영역·변경분 동기화, 계정 인증과 공용 DB, 운영 도구, HTTPS와 부하 검증이 필요합니다. 상세한 서버 구성·환경 변수·백업 주의사항은 [서버 문서](server/README.md)에 있습니다.

첫 버전에서는 장식물 충돌과 우회 경로 탐색이 없어 나무나 건물 일부를 통과할 수 있습니다. NPC·거래·퀘스트·추가 의상은 다음 확장 대상으로 남겨 두었습니다. 공동 절 진행률·채집 재생성 타이머·채팅·자리 점유는 메모리에 있으며 서버 재시작 시 초기화됩니다.

이 클라우드 작업은 이미 격리되어 있으므로 기존 `/workspace/yumjuuu` 체크아웃을 사용하세요. 사용자가 별도로 요청하지 않는 한 Git worktree를 새로 만들 필요가 없습니다.
